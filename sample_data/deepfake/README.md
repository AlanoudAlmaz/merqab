# Deepfake scan — test samples

Synthetic test files for the **Check → Deepfake scan** tab. The pictures are abstract and generated by a script. The sound files are plain tones. Each file only carries **metadata markers**, so you can see how MIRQAB reacts to them. None of them is a real deepfake.

| File | What it contains | Expected result |
|---|---|---|
| `1-stable-diffusion.png` | PNG `parameters` text chunk, written the way Stable Diffusion WebUI writes it | **AI-generation markers found** (Stable Diffusion) |
| `2-declared-ai.jpg` | XMP / IPTC `DigitalSourceType = trainedAlgorithmicMedia` | **AI-generation markers found** (the file declares itself AI-generated) |
| `3-camera-metadata.jpg` | EXIF Make/Model = Apple iPhone | No AI markers + "camera metadata present, but metadata can be edited" |
| `4-no-metadata.jpg` | Nothing, the same as an image forwarded on WhatsApp | No AI markers. This proves nothing. |
| `5-voice-tagged.mp3` | ID3 tag naming a voice generator | **AI-generation markers found** (ElevenLabs) |
| `6-voice-note-plain.mp3` | No tags | No AI markers + call-back advice |

When `OPENAI_API_KEY` is set, images also get the **AI visual review**. On these abstract test images it should report "no clear visual signs". If you want to see that review react, use a real AI-generated portrait.
